# 云环境隔离矩阵

## 隔离原则

`dev`、`staging`、`prod` 是三个完全独立的运行边界。环境之间不得共享数据库、
Redis 实例或逻辑库、对象存储桶、访问密钥和应用密钥。生产数据不得复制到非生产环境；
如测试确需相似数据，应先完成脱敏并写入专用测试资源。

每个环境应使用独立的腾讯云项目或等效资源分组、独立的 CloudBase 环境和独立的最小权限
服务账号。资源标签至少包含 `project=stay-fable`、`environment=<环境>` 和
`owner=<负责人>`。

## 资源矩阵

| 资源                 | dev                        | staging                | prod                             | 命名建议                           |
| -------------------- | -------------------------- | ---------------------- | -------------------------------- | ---------------------------------- |
| CloudBase Run API    | 开发联调，允许按需缩容     | 发布验收，配置接近生产 | 面向用户，至少两个实例           | `stay-fable-<env>-api`             |
| CloudBase Run worker | 开发异步任务，无公网入口   | 发布验收，无公网入口   | 独立扩缩容，无公网入口           | `stay-fable-<env>-worker`          |
| PostgreSQL/PostGIS   | 独立开发库，PostGIS 17/3.5 | 独立预发布库           | 高可用、备份和恢复演练           | `stay-fable-<env>-postgres`        |
| Redis                | 独立实例或独立专属集群     | 独立实例               | 高可用实例，启用传输加密         | `stay-fable-<env>-redis`           |
| COS/对象存储桶       | 测试图片，短生命周期规则   | 验收素材               | 生产图片、版本控制和生命周期策略 | `stay-fable-<env>-assets-<账号ID>` |
| 密钥与 Secret        | 独立开发密钥               | 独立预发布密钥         | 独立生产密钥，定期轮换           | `/stay-fable/<env>/<名称>`         |
| 日志/监控            | 短保留期，便于调试         | 覆盖告警流程           | 长期审计、分级告警               | `stay-fable-<env>-observability`   |
| API 域名             | `api-dev.<域名>`           | `api-staging.<域名>`   | `api.<域名>`                     | 每个环境独立证书与 DNS             |

## 环境晋级

制品应由同一次受控构建产生，并按 `dev → staging → prod` 晋级；不要在不同环境重新打包
源代码。配置和 Secret 在部署时注入，不进入镜像。数据库变更先在 `dev` 和 `staging`
验证备份、迁移与回滚步骤，再安排生产维护窗口。
